ЖАНРОВОЕ ОБЛАКО ДЛЯ ЯНДЕКС МУЗЫКИ
Техническое описание расширения
===========================================================

Кратко
-----------------------------------------------------------
«GenreCloud» (в интерфейсе — «GenreCloud») — расширение для
Chrome/Chromium и Firefox, которое читает все треки из раздела «Мне
нравится» Яндекс Музыки, определяет жанры этих треков и рисует облако
жанров, где размер слова равен числу разных любимых треков этого жанра.

Расширение не собирает статистику прослушиваний: Яндекс Музыка не отдаёт
пользователю счётчики своих прослушиваний. Один любимый трек — один голос
за каждый найденный у него жанр.

Версия: 1.0.0
Формат: Manifest V3
Платформы: Chrome/Chromium (включая Edge, Brave, Vivaldi), Firefox 128+
Лицензия/распространение: открытый исходный код, сборка локальная
(подробности в README.md проекта)

Что делает расширение
-----------------------------------------------------------
1. Собирает полный список понравившихся треков через внутренний API
   Яндекс Музыки, используя текущую сессию пользователя в браузере.
2. Сразу строит облако по «быстрым» жанрам альбомов Яндекса — карта
   появляется через пару секунд, ещё до обращения к внешним каталогам.
3. Постепенно уточняет жанры каждого трека в музыкальных каталогах:
   сначала Discogs, затем MusicBrainz (только если Discogs ничего не
   нашёл). Уточнённые жанры заменяют грубый жанр Яндекса.
4. Пересчитывает облако по мере уточнения, показывает прогресс и
   сохраняет результат, чтобы длинный проход можно было прервать и
   продолжить позже.
5. Позволяет нажать на жанр и увидеть, какие именно треки его дали, а
   также выгрузить полный результат в JSON.

На чём написано
-----------------------------------------------------------
Фронтенд (интерфейс облака):
  - React 18 + TypeScript;
  - Vite (сборка, dev-сервер, два входа: index.html и popup.html);
  - Tailwind CSS 4 через @tailwindcss/vite;
  - Radix UI (набор примитивов в стиле shadcn/ui) — диалоги, тултипы,
    прогресс, аккордеон и т. п.;
  - lucide-react — иконки;
  - собственная «редакционная» дизайн-система: тёплая бумажная палитра,
    крупная антиква в заголовках, без декоративных анимаций.

Расширение (браузерная часть):
  - vanilla JavaScript без сборщика: public/background.js и
    public/content.js;
  - манифест Manifest V3: service worker в Chrome, фоновый скрипт в
    Firefox;
  - chrome.storage.local для хранения библиотеки;
  - declarativeNetRequest (только Chrome) для добавления User-Agent
    каталогам;
  - инлайн-скрипт, внедряемый в страницу Яндекс Музыки, для запросов
    от имени самой страницы.

Упаковка:
  - Node.js-скрипт scripts/package-extension.mjs сам собирает ZIP
    (без внешних зависимостей), формирует отдельную Firefox-сборку и
    считает SHA-256 сборки.

Архитектура и поток данных
-----------------------------------------------------------
Схема:

  [вкладка music.yandex.*]                 [вкладка расширения index.html]
    content.js  ── сообщения ───────────►  React-приложение
      │ 1) инлайн-скрипт в контексте         │
      │    страницы (настоящие куки)         │ onCollect()
      │ 2) запрос из content script          │ onLookup()  ──► Discogs,
      │ 3) скрапинг DOM (резерв)             │                MusicBrainz
      ▼                                      ▼
  список треков  ────────────────────►  облако жанров + список треков

Компоненты:

1. background.js
   - По клику на иконку расширения открывает отдельную вкладку с
     облаком (index.html). Если вкладка уже открыта — активирует её.
   - При первой установке сразу открывает её.
   - Отдельная вкладка нужна потому, что попап закрывается при потере
     фокуса и прервал бы долгий поиск жанров.

2. content.js (content script на music.yandex.ru/.com/.kz/.by)
   - Слушает сообщение READ_YANDEX_FAVORITES от вкладки расширения.
   - Собирает список тремя путями по приоритету:
     а) pageCollectLikes — самодостаточная функция, которая
        сериализуется в строку и вставляется в страницу тегом <script>.
        Она выполняется в контексте страницы, поэтому запросы к API идут
        с настоящими куками и origin Яндекса. Результат возвращается
        через window.postMessage со случайным токеном.
     б) запрос к API из самого content script (работает в Chrome;
        в Firefox Яндекс отвечает 401, потому что origin расширения не
        принимается);
     в) резервный скрапинг DOM: прокрутка виртуального списка «Мне
        нравится» и чтение строк. Используется только если оба
        API-пути недоступны.
   - Собирает полный объект трека: id, название, исполнитель, альбом,
     жанр альбома Яндекса (slug), длительность, доступность.
   - Дедупликация по id трека; треки без id — по «исполнитель::название».

3. extension-runtime.ts (TypeScript, мост между React и браузером)
   - collectFavorites(): находит вкладку Яндекс Музыки, отправляет
     сообщение, ждёт ответ (таймаут 80 с), дедуплицирует треки.
   - lookupLibraryGenres(): двухфазный проход по библиотеке.
     Фаза 1 — мгновенные «семена» из жанров альбомов Яндекса.
     Фаза 2 — уточнение каждого трека в каталогах с прогрессом,
     частичной отдачей результата и сохранением каждые 5 треков.
     На каждый трек — жёсткий лимит 45 секунд, после чего остаётся
     быстрое семя, а сбор идёт дальше.
   - Загрузка/сохранение библиотеки в chrome.storage.local под ключом
     genre-cloud-library-v1 в виде { results, updatedAt }.
   - Экспорт JSON (файл yandex-music-genres.json) со всеми треками,
     жанрами, источниками и статусами.
   - Отмена поиска: флаг, который проверяется между треками.

4. catalog-service.ts (каталоги и жанровая логика)
   - YANDEX_GENRE_LABELS — таблица соответствия slug’ов Яндекса
     читаемым названиям (rock, pop, electronic, hip-hop, jazz, folk,
     soundtrack и т. д.). Нужна для мгновенного облака.
   - lookupTrackGenres(): Discogs → при пустом результате MusicBrainz.
     Если каталоги ничего не дали — остаётся жанр Яндекса.
   - Discogs: поиск релиза по названию трека и исполнителю, затем
     стили (style) и жанры (genre) релиза; при необходимости —
     запрос деталей релиза.
   - MusicBrainz: поиск записи (recording) по названию и исполнителю,
     затем запрос жанров записи. Кандидат принимается, только если
     взвешенная похожесть названия и исполнителя не ниже 0.68.
   - cleanSearchTitle(): убирает из названия ремастеры, live/remix/
     demo-пометки, feat., лишние скобки и хвосты — чтобы каталоги
     находили оригинальную запись.
   - Ограничения частоты: Discogs — интервал 2,7 с (примерно 22
     запроса в минуту без токена), MusicBrainz — 1,5 с (сервис просит
     не чаще одного запроса в секунду). До 3 попыток на запрос,
     уважение Retry-After и пауза при 503.
   - Статусы трека: matched (жанры есть), unmatched (каталоги ничего
     не нашли), error (каталог ответил ошибкой и запасного жанра нет).
     Если один каталог упал, но другой дал жанры, это не считается
     сбоем.

5. music.ts (модель и подсчёт)
   - Типы Track, TrackResult, GenreHit, GenreCount, CatalogSource.
   - stableTrackId(): `id:<id>` для треков Яндекса, иначе нормализованные
     «исполнитель::название». Ключ по id принципиален: один и тот же
     трек может лежать в библиотеке дважды (сингл и альбом), и раньше
     такие записи ошибочно схлопывались.
   - aggregateGenres(): один трек даёт не больше одного голоса за жанр
     (повторы внутри трека игнорируются), источники объединяются,
     сортировка по частоте, затем по алфавиту.
   - mergeGenreHits(): слияние жанров из разных каталогов с сохранением
     источников.

6. App.tsx (интерфейс)
   - Шапка «GenreCloud» и подпись «личная карта музыки».
   - Крупный заголовок «Вкус звучит как карта» и пояснение принципа.
   - Строка состояния: «Облако уже собрано по жанрам Яндекс Музыки —
     уточняем каждый трек в каталогах» с прогрессом N / M.
   - Облако: до 80 самых частых жанров, размер шрифта от 17 до 48 px
     пропорционально числу треков; клик по слову фильтрует список.
   - Панель «Ваша коллекция»: кнопки «Собрать жанры» / «Уточняем
     жанры…», «Остановить поиск», «Выгрузить результат», «Обновить»,
     «Очистить» (с подтверждением).
   - Статистика: любимых треков, жанров на карте, нашлись жанры,
     без совпадения, сбой каталога, вклад каждого источника
     (Яндекс Музыка / MusicBrainz / Discogs).
   - Список треков: первые 300 строк, у каждого — до трёх жанров и
     пометка «жанры не найдены».
   - Подвал: «GenreCloud · заметки о любимом» и источники данных.

Как происходит сбор (по шагам)
-----------------------------------------------------------
1. Пользователь открывает Яндекс Музыку и входит в аккаунт.
2. Нажимает на иконку расширения — открывается вкладка облака.
3. «Собрать жанры»:
   - вкладка расширения просит content script прочитать лайки;
   - content script внедряет в страницу pageCollectLikes;
   - скрипт получает uid из статуса аккаунта, запрашивает
     /users/<uid>/likes/tracks и забирает до 50 id за раз через
     /tracks?track-ids=..., повторяя сбойные пачки;
   - готовый массив возвращается в расширение и дедуплицируется по id.
4. Сразу после сбора строится облако по жанрам альбомов Яндекса и
   сохраняется в storage.
5. Запускается уточнение: для каждого трека — Discogs, при пустом
   ответе — MusicBrainz; результат заменяет семя.
6. Каждые 5 треков библиотека сохраняется; облако и статистика
   обновляются на лету.
7. При повторном запуске уже уточнённые треки берутся из кэша, поэтому
   «Обновить» продолжает работу, а не начинает заново.

Правила подсчёта
-----------------------------------------------------------
- Учитываются только треки со статусом matched.
- Один трек = один голос за каждый жанр, даже если каталог вернул
  жанр дважды в разных написаниях.
- Жанры каталогов заменяют жанр Яндекса, потому что они конкретнее
  (Shoegaze вместо Rock).
- MusicBrainz спрашивается только при пустом ответе Discogs, чтобы не
  создавать лишнюю нагрузку и не получать 503.
- Источники сохраняются у каждого жанра и показываются в статистике.

Хранение и приватность
-----------------------------------------------------------
- Список треков и найденные жанры хранятся только локально, в
  chrome.storage.local (ключ genre-cloud-library-v1).
- Никакого сервера, аккаунта расширения, телеметрии и аналитики нет.
- Во внешние каталоги уходят только название трека и исполнитель.
  Куки, токены и данные аккаунта Яндекса наружу не передаются.
- Запросы к API Яндекса выполняются в контексте открытой страницы,
  то есть теми же средствами, что и сам веб-плеер.
- «Очистить» удаляет локальную библиотеку после подтверждения.

Разрешения и зачем они
-----------------------------------------------------------
- storage — сохранение библиотеки и прогресса.
- tabs — поиск открытой вкладки Яндекс Музыки и открытие вкладки
  облака.
- scripting — внедрение скрипта сбора в страницу (Chrome).
- declarativeNetRequest — добавление суффикса GenreCloud/1.0 к
  User-Agent при запросах к MusicBrainz и Discogs (Chrome; в Firefox
  правило не нужно и удаляется из сборки).
- host_permissions — music.yandex.ru/.com/.kz/.by, api.music.yandex.*,
  musicbrainz.org, api.discogs.com.

Сборка и установка
-----------------------------------------------------------
Требования: Node.js 20+, npm, аккаунт Яндекс Музыки в браузере.

  npm install
  npm run build        # vite build + упаковка расширения
  npm run typecheck    # проверка типов

Результат сборки:
  dist/public                     распакованное расширение для Chrome
  dist/public/genre-cloud-extension.zip   архив для Chrome
  dist/firefox                    распакованное расширение для Firefox
  dist/genre-cloud-firefox.zip    архив для Firefox

Chrome/Chromium:
  chrome://extensions → режим разработчика → «Загрузить
  распакованное» → dist/public.

Firefox:
  about:debugging#/runtime/this-firefox → «Load Temporary Add-on…» →
  dist/firefox/manifest.json.
  Временное дополнение живёт до перезапуска; для постоянной установки
  нужна подпись в AMO. Для разработки удобно:
  npx web-ext run --source-dir dist/firefox

Важно: после пересборки и переустановки расширения перезагрузите не
только вкладку облака, но и вкладку Яндекс Музыки. Браузер держит
старую копию content script до перезагрузки страницы.

Отличия сборок Chrome и Firefox
-----------------------------------------------------------
Chrome:
  - background.service_worker = background.js;
  - есть declarativeNetRequest и rules.json (User-Agent для каталогов);
  - content script тоже может обращаться к API напрямую, хотя основной
    путь — всё равно внедрённый в страницу скрипт.

Firefox:
  - background.scripts вместо service worker;
  - DNR-правила удалены (Firefox не поддерживает их в таком виде);
  - manifest содержит browser_specific_settings.gecko.id и
    strict_min_version 128.0;
  - запрос к API из content script получает 401, поэтому основной путь —
    внедрённый в страницу скрипт, а скрапинг DOM остаётся резервом.

Ограничения
-----------------------------------------------------------
- Нет статистики прослушиваний: размер слова — число разных любимых
  треков. «Сколько раз я слушал» потребовало бы отдельного источника
  (например, Last.fm).
- Полный уточняющий проход по библиотеке ~700 треков занимает примерно
  30–35 минут из-за лимитов Discogs и MusicBrainz. Это не ошибка:
  каталоги бесплатные и просят не частить. Прогресс сохраняется, проход
  можно остановить и продолжить.
- Пока идёт уточнение, часть треков может оставаться с жанром Яндекса —
  это нормальное промежуточное состояние.
- Жанры зависят от полноты каталогов: редкие и локальные релизы могут
  не найтись (статус «без совпадения»).
- Нужна активная сессия Яндекс Музыки; при смене аккаунта или выходе
  сбор вернёт ошибку авторизации.
- Список «Мне нравится» должен быть доступен аккаунту; приватность
  настроек Яндекса может ограничить API.

Проверка на реальной библиотеке
-----------------------------------------------------------
Проверено в Firefox на аккаунте с 690 лайками:
- собрано 686 треков (4 трека недоступны у Яндекса);
- облако появляется сразу после сбора, без ожидания каталогов;
- дедупликация по id сохраняет треки, которые лежат в библиотеке дважды;
- уточнение продолжается из кэша: 584 из 686 треков уже имели жанры,
  сбоев каталога — 0;
- кнопка «Остановить поиск» корректно завершает проход, сохраняя
  найденное.

Частые вопросы
-----------------------------------------------------------
Почему облако сначала «грубое»?
  Жанр альбома Яндекса — один slug на релиз. Он нужен, чтобы карта
  появилась мгновенно. Каталоги затем уточняют стиль.

Почему трек не находится в Discogs?
  Бесплатный поиск ограничен, а название может отличаться (ремастер,
  feat., локализация). Расширение чистит название и пробует
  MusicBrainz; если оба пусты — остаётся жанр Яндекса или пометка
  «без совпадения».

Можно ли пользоваться без интернета?
  Нет: и сбор лайков, и уточнение в каталогах требуют сети. Офлайн
  доступен только уже сохранённый результат из локального хранилища.

Что произойдёт, если закрыть вкладку облака во время поиска?
  Прогресс сохраняется каждые 5 треков; при следующем открытии и
  запуске уточнение продолжится с сохранённого места.

Куда выгружается JSON?
  В папку загрузок браузера, файл yandex-music-genres.json: массив
  треков с жанрами, источниками, статусами и ошибками каталогов.
